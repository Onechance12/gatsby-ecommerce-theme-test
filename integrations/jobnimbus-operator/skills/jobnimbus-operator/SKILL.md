# JobNimbus Operator

Use the installed native Operator for HCN/Wave work. Source code is not an
activation: compiled release pins and live attestation control tool availability.
Do not edit a running plugin cache, bypass pins, or substitute raw APIs,
credentials, browsers or one-shot effect scripts.

## Start only what this task needs

- For live operational work after an app restart or in a new chat, read
  [session and approvals](references/session-and-approvals.md), then call
  `bridge_whoami` and `bridge_restart_verify`. Require the exact provider-attested
  build, policy/owner, runtime, historical isolation and receipt boundary.
- Reuse an already verified session within the same uninterrupted conversation;
  do not restart it on an ordinary approval reply. Each action helper freshly
  re-attests before planning/execution. Drift invalidates approval.
- For source-code maintenance only, inspect the relevant implementation and
  synthetic tests. Do not reread the client book, carrier mail, Quo history or
  unrelated operational procedures to debug a transport failure.
- Read each selected reference completely. Load only the needed modes below.

## Read-only troubleshooting

A request to investigate an operator failure authorizes relevant read-only
checks, not a new upload, access change, receipt disposition or email action.
Do not repeatedly ask for permission to inspect already in-scope evidence.

For an existing PDF quarantine, use the activated native
`pdf_receipt_diagnose` with exactly `{batchId,query,documentId}`. Read
[PDF diagnosis and disposition](references/pdf-receipt-resolution.md).
Diagnosis creates/consumes no approval, changes no receipt and releases no hold.
A privacy mismatch is a separate finding from missing/wrong PDF bytes or a
download-policy rejection. Keep these distinctions clear.

Reuse the returned as-of finding; do not repeat an unchanged failed diagnostic
or resolution plan automatically. A rejected destination is not proof its host
is wrong: report its specific URL rule and fixed host category. A hostname
fingerprint is not a URL or authorization to contact that host. Never expose
signed URLs, credentials, provider bodies or raw exceptions. Never widen trust
or remove a hold just to make a test pass.

## Invariants

Resolve an exact file before exact-file communication reads and effects. The
separately activated own-inbox sweep may discover incoming evidence first;
matches remain leads until exact-file review. Report all-assigned Insurance,
active/open, returned counts and coverage separately; never assume a 58-file
book. Current eligibility comes from the attested release: live ownership when
that policy is active, an exact roster only for a legacy fixed-file release.

Client effects require their exact current plan and explicit approval.
Draft creation is not sending; a receipt disposition is not an upload/access
change; an approved call is not writeback. Preserve wrong-file, #2628,
duplicate/replay, privacy, content-hash and one-use-approval protections.
Never use tool-repair or installation approval as client-action approval.
Unknown effects keep their audit history and hold until the approved recovery
workflow proves the result. Do not claim a notification or carrier receipt
from a saved note, draft, or send alone.

HCN client data stays out of Chance Brain, Jobrolo, shared Pages, training and
external embeddings. Company operational access is exact-file read-only, never
a company sweep or mutation. Apply the company workflow to actual client work.
